# Заметки докладчика

Десять блоков идут в порядке [слайдов](../presentation/dependency-inspector-mcp-slidev.md). На каждом достаточно озвучить основной тезис и один пример.

## 1. Проблема и цель

«Возьмём проект с фронтендом на npm и бэкендом на Python. Разработчику нужно понять, какие пакеты найдены, что известно об их лицензиях и уязвимостях и какие правила команды они нарушают. Инспектор собирает эти данные в одном месте и отдаёт их MCP-клиенту».

**Переход.** «Посмотрим, как этот результат используют разные люди».

## 2. Для кого это полезно

Разработчик открывает отчёт перед PR и видит, какой пакет стоит проверить. AppSec задаёт общую политику и получает список нарушений. Специалист по лицензиям может начать с таблицы известных и неизвестных лицензий, а затем проверить спорные пакеты по исходным материалам.

**Переход.** «Все трое работают с одними данными. Покажу, откуда они берутся».

## 3. Архитектура MCP-сервера

Сканер читает манифесты npm и Python. Остальные модули собирают сведения о лицензиях и уязвимостях, применяют политику и формируют отчёт или SBOM. Шесть MCP-инструментов открывают эти операции клиенту. Три ресурса позволяют прочитать последние результаты из памяти процесса.

«Два промпта, `audit_dependencies_and_risks` и `license_report_for_legal`, подсказывают клиенту порядок вызовов. Сервер разбирает файлы и применяет правила без LLM. Агент объясняет полученный результат».

**Переход.** «От архитектуры сервера перейду к тому, как мы организовали разработку».

## 4. Агенты и их роли

Человек задавал цель, утверждал контракт и принимал результат. Оркестратор разбивал работу на задачи. Dev отвечал за реализацию, QA и Verifier сверяли поведение с контрактом, Docs и Deploy связывали инструкции с рабочим запуском. Когда ломался сценарий в Inspector, Debugger воспроизводил конкретный сбой.

**Переход.** «Разберём один такой цикл от требования до проверки».

## 5. Этапы работы

Пройдите по цепочке на слайде от анализа домена до демо. На примере Docker сформулируйте требование: `serve` открывает `/mcp`, а `smoke` проверяет `/health`. Это требование зафиксировали в плане, реализовали в точке входа и описали в быстром старте. [План реализации](../plan/06-implementation-plan.md)

**Переход.** «На каждом этапе были решения, которые оставались за человеком».

## 6. Кто за что отвечал

«Я определял, какую проверку должен пройти результат и где проходит граница инструмента. Агент получал конкретную задачу с контрактом из репозитория. При расхождении мы возвращались к этому контракту и проверяли поведение на примере». [Архитектура и API](../plan/05-architecture-and-api.md)

**Переход.** «Вот стек, на котором это получилось собрать».

## 7. Инструменты и запуск

Python, FastMCP и Pydantic связывают парсеры и политику с MCP-инструментами. Для запуска как локального процесса есть stdio, для контейнера — Streamable HTTP на `/mcp`. Достаточно показать, где подключается клиент и где находятся файлы проекта.

**Переход.** «Дальше проверим, что сервер отвечает и клиент может выполнить сценарий».

## 8. Контроль качества

Тесты проверяют разбор манифестов, политику, SBOM и ответы инструментов. `docker run IMAGE smoke` проверяет готовность через `/health`. В Inspector отдельно подключаемся к `/mcp` и вызываем инструменты на демопроекте. `DEMO_MODE=true` даёт примеры уязвимостей без запроса к OSV.

**Переход.** «Ручной прогон нашёл две ошибки на границе с клиентом».

## 9. Что пришлось исправить

- **Ресурсы Inspector.** Клиент не мог открыть отчёт, когда обработчик возвращал Python-словарь. Обработчик теперь возвращает строку JSON с MIME-типом `application/json`. В докладе можно показать, что формат данных и формат передачи проверяются отдельно.
- **Вложенный `packages`.** Inspector в одном из вызовов прислал `[[{...}]]`. Для `suggest_dependency_replacements` сервер разворачивает эту оболочку. Для демо можно использовать обычный список из инструкции.

Из более свежих правок можно назвать проверку файла политики до аудита и явную ошибку при слишком большом манифесте. В обоих случаях пользователь узнаёт, почему полный отчёт собрать не удалось.

**Переход.** «Эти случаи хорошо показывают, почему запуск по инструкции важен и для следующего разработчика».
