# FAQ по «Инспектору зависимостей и лицензий»

## Зачем нужен MCP?

MCP позволяет вызвать проверку зависимостей из клиента, в котором разработчик уже работает с проектом. Сервер читает манифесты, применяет правила и возвращает структурированный результат. Клиент может показать его как есть или объяснить пользователю. Ядро сервера обходится без LLM.

## Какие проекты можно проверить?

Сервер поддерживает npm и Python. Он ищет `package.json`, `package-lock.json`, `pnpm-lock.yaml`, `requirements.txt`, `pyproject.toml` и `poetry.lock` в указанной директории и её поддиректориях. В смешанном проекте пакеты обеих экосистем попадают в общий отчёт. Покрытие зависит от того, какие манифесты и версии доступны в файлах.

## Как запустить демо?

Запустите Docker и пройдите [быстрый старт](../README.md#быстрый-старт). После запуска контейнера подключите MCP Inspector к `http://localhost:8000/mcp` по Streamable HTTP. В качестве пути к проекту укажите `demo_project`. В [демо](../DEMO.md) есть точные аргументы и ожидаемые ответы для двух вызовов.

## Можно ли подключиться без Docker?

Да. Установите пакет из корня репозитория командой `python -m pip install -e .` в окружении Python 3.11 или новее. В клиенте с поддержкой stdio укажите команду `dependency-inspector-mcp` из этого окружения. Относительные пути считаются от рабочей директории процесса сервера.

## Что именно показывает `DEMO_MODE`?

В режиме `DEMO_MODE=true` сервер берёт примеры уязвимостей из встроенного набора. Список пакетов, метаданные лицензий и правила политики по-прежнему берутся из переданных файлов. Это позволяет показать сценарий без обращения к OSV.

В обычном режиме сервер запрашивает OSV. При сбое `vulnerability_scan_status` становится `unavailable`, а проверка политики возвращает `compliant=false` и отмечает, что аудит неполный. Статус `demo` используется только при включённом `DEMO_MODE`.

## Как передать свои правила по лицензиям и CVE?

Укажите YAML/JSON-файл в `policy_path` или передайте объект в `policy`. Начать можно с [демонстрационной политики](../demo_project/policy_strict.yaml). В Inspector поле `policy_path` принимает обычный текст, например `demo_project/policy_strict.yaml`.

Если явно заданный файл отсутствует, недоступен или содержит некорректную политику, проверка останавливается с ошибкой. Если задан `ALLOWED_BASE_PATH`, канонические пути к проекту, файлу политики и найденным манифестам должны находиться внутри этой директории.

## Что значит лицензия `Unknown`?

Сервер не нашёл достаточных сведений о лицензии в доступных метаданных или не распознал её. Политика может считать такой случай нарушением через `deny_unknown_license`. Для решения о выпуске проверяйте лицензию по исходным материалам пакета.

## Что происходит с большим lock-файлом?

Сервер проверяет размер каждого найденного манифеста перед разбором. По умолчанию предел составляет 5 МиБ на файл. Превышение возвращает ошибку с именем файла и лимитом, который задаётся в `MAX_MANIFEST_FILE_BYTES`.

## Как сравнить две политики или результаты до и после обновления?

В одном вызове `check_policy_compliance` действует одна политика. Для сравнения вызовите инструмент дважды и сохраните ответы снаружи. Например, можно сравнить поле `violations` до и после обновления зависимости. Ресурс `report://latest` показывает последний отчёт в памяти сервера.

## В каких форматах доступен SBOM?

`generate_sbom` возвращает SPDX 2.3 JSON (`format="spdx"`) или CycloneDX 1.5 JSON (`format="cyclonedx"`). Для передачи результата другому инструменту сохраните поле `sbom` из ответа.

## Можно ли сразу применять предложенные замены?

`suggest_dependency_replacements` возвращает примеры из встроенного списка и помечает их `demo_mode=true`. Это материал для демонстрации сценария. Перед заменой проверьте совместимость, актуальную версию, лицензию и уязвимости кандидата.
